# Безопасность и конфиденциальность

## Хранение секретов
- Профили (UUID, пароли, ключи, исходные ссылки) и подписки (URL часто содержат токен) хранятся в одном файле `profiles.dat`, зашифрованном AES-256 (`FileAccess.open_encrypted`, с контролем целостности MD5).
- 256-битный ключ данных генерируется `Crypto.generate_random_bytes` и хранится только в виде, обёрнутом ключом AES-GCM из **Android Keystore** (неэкспортируемый, `KeystoreHelper`).
- На настольных платформах Keystore не используется: ключ лежит рядом с данными — это защита от случайного просмотра, о чём сказано в интерфейсе («Конфиденциальность»).
- Если ключ недоступен (сброс Keystore, восстановление на другом устройстве), база **не перезаписывается**; пользователю предлагается сброс.
- `allowBackup=false`: данные приложения не попадают в резервные копии Android/adb.
- Конфигурация активного подключения хранится во внутреннем каталоге приложения (`files/`), потому что она нужна службе в отдельном процессе и для «Постоянной VPN». Доступ к ней имеет только приложение (и root).

## Журналы и отчёты
- Каждая строка журнала маскируется **при записи** (`SecretMasker`): UUID, `password`, `uuid`, `private_key`, `pbk`, `sid`, `token`, `auth`, учётные данные в ссылках, base64-ссылки vmess, PEM-блоки.
- Диагностический отчёт дополнительно маскирует адреса серверов (оставляет TLD/первые октеты) и содержит конфигурацию с замаскированными секретами.
- Ошибки разбора подписок указывают номер строки и схему, но не содержимое ссылки.

## Сеть
- Подписки: только HTTPS с проверкой сертификата (HTTP — только по явному согласию в настройках), ручная обработка перенаправлений (≤5) с повторной проверкой каждого адреса, запрет `localhost`, `.local`, `.internal`, приватных/loopback/link-local/CGNAT/multicast адресов **после DNS-разрешения**, лимит 8 МБ, тайм-аут 25 с, проверка UTF-8. Остаточный риск: DNS-rebinding между проверкой и запросом (HTTPRequest разрешает имя повторно).
- Проверка TLS не отключается приложением. Если параметр `allowInsecure=1` пришёл в ссылке, он применяется (это решение владельца сервера) и показывается предупреждение о MITM.
- Внешние запросы приложения: подписки (по адресам пользователя), проверка IP (Cloudflare trace, отключаемо), наборы правил geoip/geosite с GitHub (только при их использовании, через прокси), цель URL-теста sing-box (`www.gstatic.com/generate_204`). Телеметрии нет.
- Буфер обмена читается только по действию пользователя (или при включённой опции «Проверять буфер обмена»), анализ выполняется локально.

## Петли маршрутизации и утечки
- Все сокеты ядра защищены `VpnService.protect()` (`auto_detect_interface`), адреса серверов разрешаются прямым DNS (`default_domain_resolver: local`).
- DNS приложений перехватывается в туннеле (`hijack-dns`); `strict_route` включён по умолчанию; IPv6 маршрутизируется в туннель (или полностью отключается настройкой вместе с DNS `ipv4_only`).
- **Kill Switch**: приложение не может запретить трафик вне VPN; используйте системные «Постоянная VPN» + «Блокировать соединения без VPN». В режиме «только выбранные приложения» остальной трафик намеренно идёт мимо VPN.
- Утверждение «весь трафик защищён» не делается, пока не выполнена проверка на устройстве (см. TESTING.md).

## Импортированные конфигурации
- JSON проверяется по структуре; неподдерживаемые типы и цепочки отклоняются; пути к локальным файлам (SSH `private_key_path`) отклоняются.
- Конфигурации не могут запускать исполняемые файлы: libbox не выполняет внешние программы, а платформенный shell явно отключён (`usePlatformShell = false`).
- Размер импортируемых данных ограничен (8 МБ, 20 000 строк, 5 000 outbounds, 16 КБ на ссылку).

## Сообщения о проблемах
Не прикладывайте к сообщениям неотредактированные конфигурации; используйте «Диагностика → Отчёт без секретов».
